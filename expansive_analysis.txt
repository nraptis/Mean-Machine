PROBLEMS AND REVIEW NOTES — MOST IMPORTANT FIRST
------------------------------------------------
1. Resolved follow-up: unused Grow cross-lane parameters were removed.
   GROW_A_B, GROW_A_C, GROW_A_D, GROW_A_E, GROW_B_B, GROW_B_C, GROW_B_D, and GROW_B_E now omit pCrossLaneA and pCrossLaneB. GROW_A_A and GROW_B_A retain both parameters because their executable loops use them. The warnings-enabled generated-code syntax check is now clean.

2. The phrase "Independent key-row flows" describes the lane slices better than it describes mutable ARX state.
   Seed stores its main Seed state to the caller before the key-box work. Key A starts from that state, and Key B is explicitly reset to that same stored Seed state. Thus A and B are state-separated branches. Inside each branch, however, rows A through H chain the mutable state from one row to the next. KEY_A_H_E and KEY_B_H_E intentionally omit the final write-back, so key-box work never replaces the caller-visible main Seed state. This is coherent and matches the established design, but a reviewer could read "independent" as meaning every row starts from the same state; it does not.

3. Saved recipe/core use is valid but not uniform in this expander.
   The 656 loops reference 569 distinct recipe files. Eighty-seven recipe identities are used twice; none is used more than twice. The generated executable text is nevertheless unique for all 656 loops because the orbiter/wanderer permutations and per-loop arithmetic material differ.
   Heart/core counts are: nexus_00=38, 01=45, 02=44, 03=40, 04=79, 05=39, 06=38, 07=39, 08=53, 09=38, 10=83, 11=39, 12=39, 13=42. Hearts 04 and 10 are represented about twice as often as the least-used hearts. Every used heart passes the structural checks below, so this is not a correctness defect; it is worth confirming if near-uniform heart representation was an intended stitching property.

4. The main src comments are deliberately summaries, not exhaustive input manifests.
   For example, a comment may say src: [$earth] while detailed generated loops also read older residual families. The named primary sources are always present. The complete per-pass Ingress and Cross comments in the ARX file match the executable reads exactly. This report treats the concise main comments according to that intended meaning.
